# 奶我助 · 第一步（软件网页版）

在本地网页上用**两个下拉列表**选条件——看哪一段时间、问日程还是任务——列出你还没交的作业
和接下来的安排。**这一步不碰语音**，只做两件事：把数据拿到、把流程跑通。

> 项目整体进度与关键决策不在这一份里，在仓库根目录的 [`PROJECT.md`](../PROJECT.md)。

一条命令起来：

```bash
bash app/run.sh
```

自己的作业全交完了、页面是空的？页头右上角有个「**演示数据**」开关，
点开就有数据可看，不联网。

---

## 界面

只有两屏。

**① 配置页** — 第一次打开、以及点右上角「设置」时看到的那一屏。
它把两个数据来源串起来：交我办日历（必需）和 Canvas 令牌（选填）。
**没导入过交我办日历就进不去主界面**，因为那一格的数据只有这个来源。
页头右上角的演示开关在配置页上也能用，所以随时能看到界面长什么样。

「已配置」的判断依据是**交我办快照文件存不存在**，不额外存标志位。
这样哪怕导进来 0 条也算配置过，不会反复把人弹回配置页。

**② 主界面** — 上面是查询条，下面是按时间排的列表。

```
时间 [ 不限时间 ▾ ]  问题 [ 全部 ▾ ]   [ 查询 ]  [ 刷新 ]        + 添加
```

**时间**（看哪一段）：

| 选项 | 含义 |
|---|---|
| **不限时间**（默认） | 不加时间限制 |
| **今天 / 明天** | 那一整天，00:00 起算 |
| **近 3 天** | 今天、明天、后天 |
| **一周内** | 今天起七天 |
| **自定义** | 自己填开始与结束日期，**含首尾两天** |

**问题**（问哪一类）：**全部**（默认，两类按时间混排）、**有什么日程**、
**有什么任务**（Canvas 作业截止）。

两条筛选规则不一样，是有意的：

- **任务（截止）**：截止时刻落在区间里，**或者已经过期还没交**——过期的永远列出来。
  选「今天」如果把上周没交的作业藏起来，那这一句就白问了。
- **日程**：和区间**有交集**，且还没结束。已经结束的不再列。

改了下拉列表**还没点「查询」**时，提示行会说"条件已改为…"，免得以为换了没反应。
自定义那两个日期框默认填好"今天 ~ 六天后"，不留空框。

「自定义」那个框反着填（结束早于开始）会被挡下来：客户端先说一句，
真去查了服务端也会返回 400 并说明原因，**不会悄悄返回一个空列表**。

「课程」没有单独一格 —— 交我办里名字带「课程 / 课表」的日历会被打上
`course_like` 标记，但它们按约定仍然记作**日程**。（一句话里可以说
「高数有什么作业」，那个能力在命令行和语音那条路上，见下面「支持的问法」。）

列表**默认只列 10 条**，多出来的收在底部「展开全部（还有 N 项）」里。
点「查询」会重置到第 10 条。

右上角「+ 添加」展开录入表单，类型只有**截止**和**日程**两种：

| 类型 | 额外字段 | 网页上的输入框 |
|---|---|---|
| **截止** | `course` 课程名 | 「课程名（可选）」 |
| **日程** | `location` 地点 | 「地点（可选）」 |

输入框的提示文字会跟着类型开关变。**添加完会把条件放宽成「不限时间 + 它所属的类型」**，
否则正选着「今天」的人记了一条下个月的，会以为没加成功。

`?tab=日程`（或 `?kind=日程`）这样的地址可以直接停在某一类上，方便存书签。

## 快速开始

### 1. 配好两个数据来源

两条都配最好，只配一条也能用——缺的那部分会在页面上明确提示。

**① Canvas（作业 / 截止）**

1. 登录 <https://oc.sjtu.edu.cn>
2. 左上角头像 → **设置**
3. 拉到页面最底部「**已批准的访问许可**」
4. 点「**+ 新建访问许可证**」，用途填 `naiwozhu`
5. 点生成 → **立刻复制**（关掉弹窗就看不到了）

保存令牌，两种方式任选：

```bash
.venv/bin/python app/cli.py --save-token    # 存到 app/config.local.json（权限 600）
export CANVAS_TOKEN='你复制的令牌'            # 或者临时用环境变量
```

> 令牌等同于密码。本项目**只把它存在你自己电脑上**，不上传任何服务器。

**② 交我办日历（日程）**

交我办没有公开 API，靠的是**你已登录的浏览器页面**里的内部接口。
`tools/browser/naiwozhu.user.js` 在那张页面上跑，用你的登录会话读数据。

同一份脚本，三种装法，差别只在**最后一步数据送到哪**：

| 装法 | 跨域那一跳谁发 | 需要什么 |
|---|---|---|
| 「奶我助」自带的扩展 | 扩展后台 service worker | 什么都不用装、不用联网 |
| Tampermonkey / Violentmonkey | `GM_xmlhttpRequest` | 一个用户脚本管理器 |
| 贴进控制台 | 不推，落成文件 | 什么都不装，但每次手动 |

三种都**不需要给本地服务加 CORS**（原因见下面「跨域那一跳」）。

**① 装「奶我助」自带的扩展**（不需要管理器、不需要联网）

1. 浏览器地址栏输入 `chrome://extensions`，打开右上角的**开发者模式**
2. 点「**加载已解压的扩展程序**」，选中 `tools/browser` 这个目录
   （配置页上直接显示这个目录的绝对路径，还有一个「复制路径」按钮）
3. 打开 <https://calendar.sjtu.edu.cn/ui/calendar>，右下角会出现「奶我助」面板

要把扩展放到别处或发给别人，配置页上还有个 [下载 zip](http://127.0.0.1:5173/naiwozhu-extension.zip)，
解压之后再选。

**② 装 Tampermonkey / Violentmonkey**

1. 装一个管理器（装一个就行，作用一样）。配置页上给了两个**国内能直连**的链接：
   - [Edge 商店 · Tampermonkey](https://microsoftedge.microsoft.com/addons/detail/tampermonkey/iikmkjmpaadaobahmlepeloendndfphd)
   - [Edge 商店 · Violentmonkey](https://microsoftedge.microsoft.com/addons/detail/eeagobfjdenkkddmbclomhiblgggliao)
   - 其他浏览器去官网按浏览器选：[Tampermonkey](https://www.tampermonkey.net/) · [Violentmonkey](https://violentmonkey.github.io/get-it/)
2. 点「**安装自动同步脚本**」（就是 <http://127.0.0.1:5173/naiwozhu.user.js>，
   管理器会拦截 `.user.js` 导航并弹安装界面）
3. 打开 <https://calendar.sjtu.edu.cn/ui/calendar>，右下角出现「奶我助」小面板

> **点「安装自动同步脚本」只是打开一段代码文本？** 说明管理器还没装好。
> 那个链接全靠管理器拦截导航，没有管理器，浏览器就只是把文件当文本打开。

> **Chrome 网上应用店国内打不开**，而里面下的 `.crx` 文件 Chrome 也不让装
> （会报 `CRX_REQUIRED_PROOF_MISSING`）。所以别去找离线包——要么走上面微软的商店，
> 要么用方式 ①。

自动同步有 30 分钟的最小间隔，避免每次翻页都重推。面板上可以随时点「立即同步」
或「下载 JSON」。本地服务没在跑的时候，面板会提示你去 `bash app/run.sh`。

**配置页会自己盯着。** 停在配置页时它每 5 秒问一次服务端；一旦脚本把数据推了进来，
页面就自己进主界面，不用手动刷新，也不用点「进入」。

**③ 什么都不装：手动跑一遍**

1. 浏览器登录 <https://calendar.sjtu.edu.cn/ui/calendar>
2. 在这张页面上按 **F12** → **Console**，粘贴脚本内容，回车
3. 会下载 `sjtu-calendar-<时间戳>.json`
4. 把这个文件拖进网页上的虚线框（或放进收件箱目录再点「从收件箱导入」）

网页上有一个「**复制脚本**」按钮，直接拿最新的脚本，不用去仓库里翻文件。

> 两种跑法都**不登录、不读 cookie、不保存密码**。脚本是在你已经登录的页面
> 自己的源里发请求，浏览器自动带上会话；数据只送到 `127.0.0.1`，不经过任何第三方。
> 会话过期后重新登录即可。

### 2. 跑起来

**本地网页版**（一条命令）

```bash
bash app/run.sh                  # 默认 5173 端口，自动打开浏览器
bash app/run.sh --port 5199      # 换端口
bash app/run.sh --no-browser     # 不自动开浏览器
```

只监听本机回环地址，不对外网开放。按 `Ctrl+C` 退出。

没有 `.venv` 时脚本会直接告诉你建它的两条命令：

```bash
python3 -m venv .venv
.venv/bin/pip install -r app/requirements.txt    # 只要 Flask 和 requests
```

**命令行版**（最快，先验证数据能不能拿到）

```bash
.venv/bin/python app/cli.py                      # 查全部未交作业
.venv/bin/python app/cli.py "明天有什么要交的"     # 自然语言提问
.venv/bin/python app/cli.py --days 7             # 只看 7 天内
.venv/bin/python app/cli.py --all                # 连没写截止时间的也显示
.venv/bin/python app/cli.py --whoami             # 只验证令牌，打印姓名和学号

.venv/bin/python app/cli.py --inspect-calendar <文件>   # 只看文件里有什么
.venv/bin/python app/cli.py --import-calendar  <文件>   # 导入
.venv/bin/python app/cli.py --scan-inbox                # 从收件箱导入最新的一份
.venv/bin/python app/cli.py --show-calendar             # 列出已导入的日程
```

也可以直接 `.venv/bin/python app/server.py`，效果和 `run.sh` 一样。

**Windows**（解释器在 `.venv\Scripts\`，所以另有一份 PowerShell 入口）

```powershell
.\app\run.ps1                  # 起网页版
.\app\run.ps1 -Port 5199 -NoBrowser
.\app\run.ps1 -Tests           # 跑四套测试
```

`app/run.sh` 与 `app/run_tests.sh` 也会自己找解释器（先看 `.venv/Scripts/python.exe`、
再看 `.venv/bin/python`），所以装了 Git Bash 的话那两个也能用；Windows 上直接跑 `.ps1` 更省事。

## 演示模式

**打开后不联网，用编好的数据演示。**

```bash
curl -X POST -H 'Content-Type: application/json' \
     -d '{"on":true}' http://127.0.0.1:5173/api/demo
```

页头右上角有一个「演示数据」开关，点它就开。开启时页面顶部会有一条橙色横幅
明确写着数据是编的。

它解决的是一个很实际的问题：**你的作业全交完了，页面打开就是空的**，功能没问题
但没法给人看，也没法在没网、没登录的场合演示。

几条设计上的约定：

- **语义是一句话**：演示模式 = 用演示数据顶替 Canvas。开了就不调 Canvas、
  一次网络都不打；本机数据（交我办导入 + 手动录入）照常参与。所以开着演示模式
  再加一条手动记录，它会立刻出现在列表里。
- **它能绕过配置门槛**：没导入过交我办日历也进得去主界面，配置页上的那个开关
  一样有效。给别人演示的时候不用先配置任何东西。
- **日期相对"现在"现算**（见 `demo.py`），今天要交的就永远是今天。
  写死日期的话过两天再演示就全变成过期了。
- **只有开关落盘**，存 `app/data/demo.json` 一个布尔值；演示条目本身每次重新生成，
  永远不可能混进 `calendar.json` / `manual.json`。删掉 `app/data/` 就等于彻底复原。
- `GET /api/status` 里的 `demo` 字段是当前状态，`demo_count` 是条目数。

演示数据覆盖了两类日期、三种时间状态（已过期 / 今天 / 将来）和窗口边界
（故意留了一条落在「这周」之外，用来确认时间窗过滤真的在起作用）。

## 两种日期类型

这是这个项目的核心约定。两类时间的语义不同，所以存法也不同：

| 类型 | 含义 | 存什么 | 默认来源 |
|---|---|---|---|
| **deadline** | 有"必须完成/提交"的性质 | 一个截止时刻 | Canvas |
| **日程** | 有起止时间的一段安排，出席即可 | 起 + 止（可全天） | 交我办日历 |

**类型由来源决定，自行录入的必须自己说明是哪一种。**

网页上的「手动添加」有明确的类型开关。接口层面，`POST /api/manual` 不带
`kind`、或 `kind` 不是这两个值之一，会被直接拒绝（HTTP 400）——宁可报错，
也不猜一个类型写进去。语音录入将来走同一个接口，所以这条约束在语音端同样成立。

## 查询缓存

Canvas 抓一次要遍历所有课程逐页翻，比较慢。所以 Canvas 那一路的结果会被缓存
**120 秒**（`NAIWOZHU_CACHE_TTL` 可改，设 0 等于关掉），不同问法共用同一次抓取。

- 缓存的是**未经筛选**的全量结果，时间窗和课程筛选在内存里做。
- **出错不写进缓存**——否则一次网络抖动会被放大成两分钟不可用。
- 同一秒内没碰 Canvas 的情况（只问日程、开着演示模式），返回的 `cache_age` 是
  `null`，含义是"这次回答用到的 Canvas 数据有多旧"。
- 网页上的**「刷新」按钮**跳过缓存重新取一次，查询提示行会显示
  「Canvas 数据更新于 HH:MM」。

## 自动同步交我办

`tools/browser/naiwozhu.user.js` 一份文件，跑在三种环境里，靠"有没有这个能力"判断：

```js
const hasGM  = typeof GM_xmlhttpRequest === 'function';       // Tampermonkey 等
const hasExt = !!(chrome.runtime && chrome.runtime.id);       // 「奶我助」扩展
const canAuto = hasGM || hasExt;    // 能自动推 → 挂面板；否则只能下载文件
```

| 环境 | 触发 | 数据送到哪 |
|---|---|---|
| 扩展 | 打开日历页自动跑 | 发消息给后台，后台 POST 给 `127.0.0.1:5173` |
| 管理器 | 打开日历页自动跑 | `GM_xmlhttpRequest` POST 给 `127.0.0.1:5173` |
| 控制台 | 你手动回车 | 下载 JSON，你再拖进来 |

### 跨域那一跳为什么单独拎出来

浏览器不允许**网页**随手往 `http://127.0.0.1` 写数据——那正是跨域规则在管的事。
要给 `fetch` 放行，本地服务就得加 CORS 头；而只要加了，**你浏览器里访问的任何
一个网页都能往你的本地服务 POST**，伪造日程或者把你的课表读走。

所以两条自动路径都是让"有权限的一方"代发，**本地服务一行 CORS 都不用加**，
那个风险面直接不存在：

- **扩展** → 后台 service worker。`manifest.json` 里声明了
  `host_permissions: ["http://127.0.0.1/*"]`，它就能直接请求本机。
  这也是为什么扩展要拆成两个文件：内容脚本只干"在日历页上取数"，
  把"碰网络"集中在 `background.js` 里。
- **管理器** → `GM_xmlhttpRequest`，配合 `@connect 127.0.0.1` 白名单。

### 自动同步为什么有最小间隔

打开一次页面就推一次是浪费。默认 30 分钟内只推一次，面板上可以手动覆盖。
重复推送本身是安全的：脚本和「奶我助」都按 `exported_at` 判新旧，旧数据会被忽略
（面板上会显示"这次跳过"）。

这个时间戳存在扩展的 `chrome.storage.local` 或管理器的 `GM_setValue` 里。
贴进控制台跑的时候只在内存里记，**不去动交我办页面自己的 `localStorage`**。

### 它做不到的

**三种装法都不是后台任务**，浏览器关着就不会同步。要真正无人值守，得用持久化浏览器配置
加定时任务（让浏览器自己带着会话发请求，不读也不导出 cookie），重得多，这个阶段没做。

### 关于 Chrome 网上应用店

国内打不开，而且**里面下的 `.crx` 文件 Chrome 也不让装**
（`CRX_REQUIRED_PROOF_MISSING` —— Chrome 只认商店直接安装的扩展）。
所以"离线 crx 包"这条路根本走不通，别去找。

能用的两条：微软的 Edge 商店（国内一般能直连，配置页上有链接），
或者「奶我助」自带的扩展（完全不联网）。

### 自动同步为什么有最小间隔

打开一次页面就推一次是浪费。默认 30 分钟内只推一次，面板上可以手动覆盖。
重复推送本身是安全的：脚本和「奶我助」都按 `exported_at` 判新旧，旧数据会被忽略
（面板上会显示"这次跳过"）。

这个间隔存在用户脚本管理器里（`GM_setValue`）。贴进控制台跑的时候只在内存里记，
**不去动交我办页面自己的 `localStorage`**。

### 它做不到的

**它不是后台任务**，浏览器关着就不会同步。要真正无人值守，得用持久化浏览器配置
加定时任务（让浏览器自己带着会话发请求，不读也不导出 cookie），重得多，这个阶段没做。

## 文件说明

| 文件 | 作用 |
|---|---|
| `model.py` | **两种日期类型的数据模型**，网页版和语音版共用 |
| `demo.py` | 演示数据：按当前时间现算的假数据，覆盖两种类型和三种时间状态 |
| `config.py` | 读取令牌：环境变量优先，其次 `config.local.json` |
| `canvas_client.py` | Canvas REST API 客户端（认证 + **自动翻页**） |
| `ddl_service.py` | Canvas → deadline：汇总未交作业、去重、排序 |
| `calendar_import.py` | 交我办导出的 JSON → 日程条目（字段名容错在这一层） |
| `store.py` | 本地仓库：日历导入快照 + 手动录入 + 演示开关，按时间戳判新旧 |
| `query.py` | 把输入规范化成查询条件：下拉列表的区间（`resolve_range`）、一句话的解析（`parse`），都是纯规则，不用大模型 |
| `console.py` | 输出被重定向时把编码切成 UTF-8。不加的话 Windows 上 `✓ ✗ ⚠` 在 GBK 里编不出来，测试会以退出码 1 假失败 |
| `cli.py` | 命令行入口 |
| `server.py` | 本地网页服务（Flask）+ Canvas 查询缓存 |
| `static/index.html` | 网页界面（原生 JS，无构建步骤） |
| `run.sh` | 一键启动网页版（自动找 `.venv/Scripts` 或 `.venv/bin`） |
| `run.ps1` | Windows 上的入口：`-Tests` 跑测试，其余同 `run.sh` |
| `requirements.txt` | 运行期依赖，只有 Flask 和 requests |
| `test_query.py` | 查询条件的 39 项用例：① 一句话的解析 19 项 ② 下拉列表的时间选项 20 项 |

浏览器端的东西都在 `../tools/browser/`，见那里的 README：

| 文件 | 作用 |

## 怎么验证"做对了"

```bash
bash app/run_tests.sh          # 四套测试一起跑，共 222 项
.\app\run.ps1 -Tests          # Windows 上等价的一条
```

输出里的 `✓ ✗ ⚠` 走的是终端的编码：真终端里 Windows 用 WriteConsoleW 没问题，
**重定向到文件或管道**时由 `console.py` 自动切 UTF-8，所以两种情况都不会假失败
（想复现原始问题：设 `NAIWOZHU_NO_UTF8=1` 再重定向）。

`test_ddl.py` 重点覆盖两件**最容易静默出错**的事：

- **翻页**：Canvas 默认每页只返回 10 条，漏翻会少拿作业而**程序不报错**。
  测试用两页的模拟数据验证 `Link` 头被正确跟随。
- **去重**：`/users/self/todo` 和「逐课程查 assignments」会返回同一条作业，
  合并时按 id 去重，并记录它来自哪些渠道。

`test_store.py` 覆盖导入链路的三个易错点：

- **字段名容错**：交我办接口没有公开文档，`startTime` / `start_time` /
  `allDay` / `all_day` 这些写法都试一遍。
- **时间戳新旧**：拖进一个旧的备份文件时，**不许**覆盖掉更新的数据。
- **类型必填**：手动录入缺类型 / 缺时间都要报错。

`test_server.py` 覆盖前几套完全没碰过的服务层。它把 Canvas 客户端换成假的，
所以**不联网**也能跑，重点盯四件事：

- **演示模式真的离线**：开着的时候断言假客户端被调用 0 次。
- **缓存在省流量**：连查两次只抓一次 Canvas；`refresh: true` 能穿透缓存。
- **时间范围真的在筛**：每个选项各来一遍（含跨天的内容、跨天的日程、
  已结束的日程），并且断言选「今天」时**过期没交的作业还在**。
  这些用例的时间全是相对"现在"造的，写死日期过几天就会跑不过。
- **测试不碰你的真实数据**：数据目录和令牌文件都被指到临时目录，
  跑完就删。你 `app/config.local.json` 里的令牌不会被覆盖。

还有一条防改歪的检查：**网页上那六个下拉选项和服务端 `query.RANGES` 必须一字不差**
（连"近 3 天"中间那个空格都算），两边改歪任何一处都会让测试红。

## 支持的问法

网页上是两个下拉列表，条件从列表里选，不靠猜：

| 时间 | 问题 |
|---|---|
| 不限时间 / 今天 / 明天 / 近 3 天 / 一周内 / 自定义 | 全部 / 有什么日程 / 有什么任务 |

命令行（以及第二步的语音）还能直接问一句话，走的是同一个接口的 `text` 字段：

```
我还有哪些作业没交          → 只列 deadline
明天有什么要交的
高数有什么作业

我明天有什么日程            → 只列 日程
下周有哪些课和考试

这周有什么安排              → 两种按时间顺序混排
```

**否定句会被当成陈述，不去查数据**：

```
明天没什么要交的     → 不查
我作业都交了         → 不查
没有作业了           → 不查
```

判断不了的输入会明确说「没听懂」，**不会猜一个答案**——
答错会让你误判自己有没有作业。

两条路最后都落到同一组条件上，所以**换输入方式不用动筛选逻辑**：
下拉列表给的是"哪几天"（`range`），一句话给的是"从现在起多少天"（`days`），
都折成一个半开时间区间再交给同一套判断。

## 已知限制

- **看不到只在微信群里布置的作业**。接口只能拿到平台上有记录的那些，
  这类要靠手动录入补。
- **交我办那条链路要你人在浏览器前点一下**。会话 cookie 是凭据，
  没有它就读不到数据，所以它做不成后台常驻任务。
- **`/users/self/todo` 在各校实例上的行为可能不同**。如果它返回为空，
  程序会自动依赖逐课程查询那条路径（返回结果里会体现来源）。
- **网页上的筛选条件只有"时间 + 类型"两格**。按课程筛（「高数有什么作业」）
  只在命令行和语音那条路上有；网页上没有第三个下拉，也就没有这个入口。
- 课程简称映射表（`query.py` 里的 `COURSE_ALIASES`）需要按你自己的课表改。
- Canvas 令牌**没有过期时间**，建议测完去设置页撤销，需要时再生成。
- 交我办日历里有些日历本身就是课表性质，导入时会打上 `course_like` 标记，
  但类型仍按约定记作「日程」。
- **缓存有 120 秒的窗口**。刚在 Canvas 上交掉一份作业，网页上最多还会显示两分钟；
  点「刷新」可以立刻看到最新状态。
- 演示模式是**服务端的一个标志**，换个浏览器打开还是同一个状态。
  想彻底回去就关掉开关，或者删掉 `app/data/demo.json`。
