# 奶龙语音终端（Windows / 树莓派通用）

> 这个目录是从组内仓库 [`walkerljy/naiwozhu-terminal`](https://github.com/walkerljy/naiwozhu-terminal)
> 同步过来的（作者 刘嘉远，见 [LICENSE](LICENSE) 与 [来源与上游同步.md](来源与上游同步.md)）。
> 放在同一个仓库里，是为了「一个 clone 就能把终端和电脑端都跑起来」；
> 上游有更新时按那份说明同步，别两边各自改。

**奶龙只是一个终端**：只负责听和说。数据（Canvas 作业、交我办日程、手动录入）都在
电脑端的 Flask 服务里，接口和分工见 [INTEGRATION.md](INTEGRATION.md)。

```
[麦克风] → 唤醒词(离线 Vosk) → 应一声"我在" → 录音断句 → 本地转写
        → LLM 只做一件事：把同音错字纠回来，输出查询参数（kind/range/…）
        → backend.py 请求电脑端 /api/query
        → tts.py 套模板 + 拼预生成音频 → [喇叭]
```

两个设计要点：

- **LLM 只做理解，不碰数据**。它只吐 `kind/range/course` 这类参数，
  非法值被 `llm._clean()` 收进白名单，所以模型抽风也不会编出一个假作业。
- **为什么还要 LLM**：语音识别会把"课"听成"可"。电脑端的 `query.parse()` 按关键词
  判类型，一错字类型就判错；终端先纠字再给结构化参数，就绕开了这一层。

## 识别准确率：两级解码

唤醒和指令的要求正好相反，所以用两个引擎：

| 阶段 | 引擎 | 为什么 |
|---|---|---|
| 唤醒（常驻） | Vosk 小模型 | 流式、边听边出字、几十 MB、树莓派也扛得住 |
| 指令（只跑一次） | **百度短语音**（默认）→ whisper → vosk | 更准；只说一句，慢 0.5 秒值得 |

实测（12 句本领域话术，字符错误率 CER，越低越好）：

| 条件 | vosk-small | whisper-base | **cloud-baidu** |
|---|---|---|---|
| 干净 | 9.2% | 7.1% | **2.1%** |
| 信噪 15dB | 10.4% | 13.1% | **2.1%** |
| 信噪 8dB | 24.3% | 25.6% | **2.1%** |
| 音量偏小 | 10.0% | 10.0% | **2.1%** |
| 每段耗时（2.8 秒音频） | 2033ms | 828ms | **约 500ms** |

云端那 2.1% 只剩一个错字：`奶龙` → `奶农`（正好在唤醒别名里，不影响）。
**12 句里 11 句完全正确**，而且噪声下几乎不掉——本地模型在 8dB 时已经掉到 24%。

读法：

- 有网就用云（`auto` 会自动选它）。
- 断网、额度用完 → 自动退回 `whisper-base`（7.1%），再不行退回 Vosk。
- 完全不想联网：`ASR_ENGINE=whisper`（要装 faster-whisper）或 `ASR_ENGINE=vosk`。
- 树莓派建议 `ASR_ENGINE=vosk`：省电，且不用等第二级。

**没装 whisper、也没配云也能跑**，只是准确率回到上面 vosk 那一列。

### 唤醒词为什么"死活听不出"

用实验查清楚过：给 Vosk 一个只含候选词的语法表，看它认不认。

```
奶龙       ❌ 不在词表        奶         ✅ 在词表
奶农       ✅ 在词表          龙         ✅ 在词表
那楼       ❌ 不在词表        你好       ✅ 在词表
奶龙你好   ❌ 不在词表        内容       ✅ 在词表
```

**"奶"和"龙"单字都在词表里，但语言模型不认识"奶龙"这个词**——它训练语料里没有。
所以解码时 奶+龙 的概率输给 哪+种、奶+农 这些常见词组合，模型就被迫输出那些。

**这不是阈值问题，调任何置信度阈值都救不回来**：模型压根不会输出这两个字。

### 解法：按读音匹配，不按字匹配

`奶龙你好` = `nailongnihao`。把识别结果也转成拼音再比相似度：

| 实际说的话被听成 | 拼音 | 相似度 |
|---|---|---|
| 奶农你好 | nainongnihao | 0.92 |
| 买龙尼好 | mailongnihao | 0.92 |
| 海龙你好 | hailongnihao | 0.92 |
| 哪种你好 | nazhongnihao | 0.83 |
| 内容你好 | neirongnihao | 0.83 |
| 哪笼鸟 | nalongniao | 0.83 |
| 那楼你好 | nalounihao | 0.75 |
| **你好**（只有你好） | nihao | **0.42** |
| 我今天有什么课 | wojintianyoushenmeke | 0.20 |

该唤醒的都在 **0.67~0.92**，正常说话都在 **0.20~0.42**，中间有 0.25 的鸿沟。
阈值取 **0.55**：

```powershell
$env:WAKE_SIMILARITY="0.55"   # 老被误唤醒就调高，老是漏就调低
```

实测 12 句误听 **全部召回**，12 句正常说话 **零误唤醒**。

匹配是三层，从严到松：精确别名 → 同音字族正则 → 拼音相似度阈值。

### 唤醒为什么还是本地
唤醒**不能**换成百度：短语音接口是非流式的，要整段上传再等结果。常驻监听得每秒传一次，
5 万次/天的额度不到 14 小时就烧完。

所以唤醒保持 Vosk 流式，但加了**云端复核**兜住它的短板：

| 信号 | 处理 |
|---|---|
| 强信号（别名命中 / 同音字族正则） | 直接唤醒，零网络 |
| 弱信号（只听见"你好"，"奶龙"没听出来） | 攒 2.5 秒音频送云端复核，确认才唤醒 |
| 复核没通过 | 静默继续听，用户无感，不消耗唤醒感 |

弱信号的存在很关键："你好"是常用词，Vosk 几乎不会听错；"奶龙"是词表外词，几乎必错。
实测 Vosk 一直只吐"那句你好"时，靠复核仍然能唤醒成功。

两个节流点（否则每 100ms 会发一次云请求）：候选出现 0.6 秒后才复核，且 1.5 秒内最多一次。

### 该分开说还是一口气说完

**默认分开说**：先说唤醒词 → 听到"我在" → 再说请求。

原因很物理：播"我在"的那 0.4 秒里**麦克风不收声音**（音频流在唤醒时关掉了）。
一口气说完的话，中间那半句正好落在这个空窗里，会丢字。

想一口气说完就关掉应答音：

```powershell
$env:ACK="0"
```

这样唤醒后立刻开始录，预录缓冲（1.2 秒）加上后续录音能覆盖整句，
唤醒词会被 `_strip_wake` 从转写结果里去掉。

> 代码里还有个尽力而为的判断：唤醒后先偷看 0.3 秒，如果在说话就不放应答音。
> 但实测 Vosk 报出唤醒词时，用户往往还没说完（尾部还有半秒静音），
> 所以这个判断经常看到的是静音——**别指望它，靠 `ACK` 选一种节奏**。

### 第三级：联网 ASR（默认已启用）
本地模型有上限。配好凭据后 `ASR_ENGINE=auto` 会自动优先用云端：

```powershell
$env:CLOUD_ASR_PROVIDER="baidu"          # 或 openai
$env:CLOUD_ASR_KEY="你的 API Key"
$env:CLOUD_ASR_SECRET="你的 Secret Key"   # 只有 baidu 要
$env:CLOUD_ASR_DEV_PID="1537"            # 1537=标准版；极速版填 80001
```

| provider | 是什么 | 注册成本 |
|---|---|---|
| `baidu` | 百度短语音识别，纯 HTTP（换 token + base64） | 免费 5 万次/天，国内直连 |
| `openai` | 任何 OpenAI 兼容的 `/audio/transcriptions` | SiliconFlow / Groq / 自建 faster-whisper 服务都能填 |

百度那个 `dev_pid` 决定走哪个端点，**填错会报 3302 无权限**：
标准版 `1537` → `server_api`；极速版 `80001` → `pro_api`。

单独验证 key（不用起整个助手）：

```powershell
python cloud_asr.py 某段音频.wav
```

**它不会让你更脆**：云识别失败（断网、欠额度、key 过期）会自动退回本地的
whisper/Vosk，只在控制台打一行提示。演示现场断网也不会罢工。

三个要自己权衡的点：音频会离开本机（课表内容会上传到第三方）、
多一次网络往返（0.2~0.6 秒）、有免费额度上限。

## 现在能做什么

| 说法 | 实际动作 |
|---|---|
| 我还有哪些作业没交 / 明天有什么要交的 | `/api/query`，kind=deadline |
| 我今天有什么课 / 下周有什么安排 | `/api/query`，kind=日程 |
| 高数有什么作业 | 带 `course_kw` 查 |
| 删掉明天的高数 / 把学生会例会隐藏 | 先复述确认，再 `DELETE /api/item/<id>`（手动条目删除、交我办条目隐藏） |
| 撤销 | `POST /api/item/<id>/restore`，恢复上一条删除 / 隐藏 / 改期 |
| 把明天第一节改到下午两点 | 确认后改期：手动条目直接 `PATCH`；交我办的走「先加后隐」 |
| （到点自动开口） | 早间 8 点念今天的安排、晚间 10 点念明天的、日程前一小时提前提醒 |

几个必须知道的语义：

- **写操作只在本机生效**。改动只落在电脑端那份数据里，交我办和 Canvas 一个字都不会变，
  所以播报里会补一句「只在本机生效；交我办里的课表还是原样」。
- **交我办的课表不能就地改时间**。改期是两步：先加一条新的、再隐藏原来那条
  （顺序固定，新增失败就不隐藏，免得两条都没了）。手动录入的条目才能直接改。
- **删 / 隐藏 / 改期都要确认**。它会先复述「要删掉明天上午八点的高等数学吗？」，
  你说「对」才写；说「不对 / 算了」就取消。找不到或有多条时会让你选第几条。
- **Canvas 的截止时间改不了、也删不掉**（409），这是设计上定的：截止时间以 Canvas 为准。

## 到点提醒

判定全在电脑端（它知道条目、隐藏状态和时间窗），**念的时机在这边**（这边才有喇叭）：

| 位 | 默认时刻 | 念什么 |
|---|---|---|
| `morning` | 08:00–12:00 | 今天的日程 + 今天截止 + 已过期未交（排最前） |
| `evening` | 22:00–次日 02:00 | 明天的日程 + 明天截止 |
| `soon` | 日程开始前 60 分钟内 | 这一条单独提前提醒 |

- 后台每 180 秒问一次「现在该念什么」，**空闲才念**：正在听、正在播报、正在等你确认时跳过。
- 同一个位 / 同一条只念一次（按 `remind_id` 去重，记在内存里；重启后会重念当前窗口内的）。
- 没到点什么都不说——空列表是「没事」，不是「提醒出错」。连不上电脑端也静默跳过。
- 单独看它现在会念什么（不用等点）：

```bash
python assistant.py --remind            # 只问一次
python assistant.py --remind --preview  # 三个位都算一遍，不管现在几点
```

提醒时刻想改，在电脑端改 `config.local.json` 的 `remind_morning` / `remind_evening` /
`remind_before_min`，或设环境变量 `NAIWOZHU_REMIND_*`，终端这边不用动。

## 第一次跑

```bash
python -m pip install -r requirements.txt
cp local_secrets.example.py local_secrets.py        # 填 LLM_API_KEY（Windows 用 copy）
python download_model.py               # 下载 Vosk 中文小模型（约 40MB）
python assistant.py --say "我今天有什么课"
```

已经能用真实数据跑通了。再上语音：

```bash
python assistant.py
python assistant.py --denoise         # 教室/宿舍这种有持续底噪的环境
```

树莓派额外装 PortAudio：`sudo apt install -y libportaudio2`；
接外接麦/声卡时分别指定设备：`IN_DEVICE=2 OUT_DEVICE=1 python3 assistant.py`。
设备名或索引都可以，用 `python -c "import sounddevice as sd; print(sd.query_devices())"` 查。

### 两个"和别人机器不一样"的地方

- **模型接口默认走校内网关**（`LLM_BASE_URL=https://models.sjtu.edu.cn/api/v1`）。
  不在校园网里的话换成任意 OpenAI 兼容地址，例如 `LLM_BASE_URL=https://api.deepseek.com/v1`。
- **语音素材不进版本库**（体积大，按机器生成）。想先听声就先拿系统语音占位：

  ```bash
  python gen_voice.py --provider sapi     # Windows 自带语音，约 120 条
  ```

  不生成也能跑：`speak()` 找不到素材时会把该说的话打印出来，只是不出声。
  `--from-api` 那一步需要电脑端服务在跑（向它取课名/教室），没有就跳过。

## 先测一遍（不用等奶龙素材）

素材还没生成也能跑，播报会自动退化成终端打印。三步，从最容易出问题的往上：

**1. 麦克风 / 唤醒词自检**（不联网、不调大模型）

```bash
python assistant.py --check
```

依次打印音频设备、语音阈值、让你随便说一句、再让你说唤醒词（12 秒）。
唤醒词没反应就看 `[stt] 听到:` 实际识别成什么，把它加到 `WAKE_WORD` 里（可写多个，逗号分隔）。
实测这个模型把 `你好小助手` 识别成 `你好 小助手`，去掉空格后正好命中，默认值可用。

**2. 文字链路**（不占麦克风）

```bash
python assistant.py --say "我今天有什么课" --no-tts
DEBUG=1 python assistant.py --say "我今天有什么课" --no-tts    # 顺带看 LLM 抽出的 JSON
```

**3. 完整语音 + 听得见的回答**

```bash
python assistant.py --system-tts       # 用系统语音念（还没有奶龙素材时的临时方案）
python assistant.py                    # 只打印不发声
```

Windows 上 `--system-tts` 走 System.Speech，要装中文语音包（本机已有 Microsoft Huihui）；
树莓派走 `espeak-ng`（`sudo apt install espeak-ng`，音质很差，只为听个响）。
奶龙素材生成好之后去掉这个开关，就是正式音色。

## 电脑端

终端不直接访问交我办，也不碰 Canvas 令牌——那些都在电脑端。

```bash
# 电脑上（队友的仓库）
.\app\run.ps1                    # 起服务，默认 http://127.0.0.1:5173

# 终端上
python assistant.py --say "我还有哪些作业没交"
```

树莓派连 PC 时把地址换成电脑的 IP（同网段或 ZeroTier 都行）：

```powershell
$env:BACKEND_URL="http://192.168.3.86:5173"
$env:BACKEND_TOKEN="和电脑端 NAIWOZHU_ACCESS_KEY 同一个值"
```

电脑端那边要先允许外部访问（**不设口令会拒绝启动**）：

```powershell
.\app\run.ps1 -BindHost 0.0.0.0 -AccessKey '你的口令'
```

本机访问（127.0.0.1）一律不需要口令，所以只在一台机器上跑时不用管这些。

## 数据新鲜度：只有一项会旧

交我办的登录会话在**电脑的浏览器里**，终端（哪怕树莓派自己跑服务）拿到的只是一份快照。
所以三类数据的新鲜度完全不同：

| 数据 | 依赖登录态 | 会不会旧 |
|---|---|---|
| Canvas 作业截止 | ❌ 用令牌，无会话 | 不会，每次现抓 |
| 交我办日程 / 课表 | ✅ 浏览器会话 | **会**，取决于电脑上最后一次推送 |
| 手动录入 | ❌ | 不会，本地即时写入 |

因此播报**日程**时，如果快照超过 `STALE_HOURS`（默认 24 小时）没更新，会补一句：

```
有一个安排。最近的是高等数学，明天上午八点，在上院100。课表已经三天没更新了，可能不是最新的。
```

作业类回答不会补这一句——Canvas 每次现抓，没有登录态可掉。想让它更早提醒就把
`STALE_HOURS` 调小（比如 6）。

要让快照保持新鲜，唯一的办法是**让电脑上那个日历页面开着**（同步脚本最小间隔 30 分钟，
且需要页面在跑）。最省事的做法是 pin 一个标签页。

## 语音素材（奶龙音色）

运行时**不调用任何 TTS**，只播预生成的 wav。规则：**文件名就是它读的文字**。

```bash
python gen_voice.py --from-api --list                     # 先看要生成哪些（连电脑端取词）
python gen_voice.py --from-api --provider edge            # edge-tts 卡通女声（当前默认）
python gen_voice.py --from-api --provider sapi            # Windows 自带语音（Huihui）
TTS_CMD="python nailong.py --text {text} --out {out}" python gen_voice.py --from-api --provider cmd
```

三种生成器：

| provider | 用途 |
|---|---|
| `edge` | edge-tts，中文 `Cartoon` 标签下最接近卡通角色的是 **Xiaoyi**（卡通女声）。可调音高语速 |
| `cmd` | **你自己的奶龙引擎**，`TTS_CMD` 里用 `{text}` `{out}` 占位。真·奶龙走这条 |
| `sapi` | Windows 自带语音（Huihui），不联网，差但最省事 |

### 唤醒应答用角色原声

`resources/voice/_ack.wav` 存在时，唤醒应答直接播这个文件——可以放角色自己的录音，
不受"文件名=文字"那套拼接规则约束（它是一整段录音，不是切片）。

放一段角色的原声（如把"我是奶龙"截下来），唤醒时就会听到真人的声音，
其余回答仍然用合成音色。没有这个文件就退回模板里的"我在"。

### 关于"奶龙音色"

**edge-tts 里没有"奶龙"这个音色**——它是版权角色的声音，公开 TTS 不会提供。
目前能做到的是**同类型的卡通音色**（Xiaoyi）加一点音高调整：

```powershell
$env:EDGE_VOICE="zh-CN-XiaoyiNeural"
$env:EDGE_PITCH="+40Hz"      # 抬高更稚气
$env:EDGE_RATE="+10%"        # 语速稍快，更活泼
python gen_voice.py --from-api --provider edge --force
```

要真正克隆奶龙的声音，只有两条路：

| 方案 | 需要什么 | 注意 |
|---|---|---|
| 在线声音复刻（火山/阿里 CosyVoice） | 账号 + 3~10 秒干净参考音频 | 大多要实名/付费，且有版权审核 |
| 本地克隆（GPT-SoVITS / Fish-Speech） | 参考音频 + 部署（无 GPU 也能跑，只是慢） | 两百多条短片段是**离线批量**生成，慢一点无所谓 |

任一方案跑通后，接进来只要一条命令：把它的调用写成 `TTS_CMD`，用 `--provider cmd` 重跑，
素材格式完全一样，识别和播报的代码一行都不用改。

奶龙引擎就绪后换 provider 重跑一遍（`--force` 覆盖）即可，素材格式完全一样。

`--from-api` 会向电脑端要全部条目的标题 / 课程名 / 地点，实测取到 15 个词、
连同模板片段和常用字一共 **183 条**。词会被规整成能念的形式：

| 原始写法 | 念出来的 |
|---|---|
| 程序设计思想与方法（C++） | 程序设计思想与方法 |
| 高等数学I | 高等数学 |
| 上院100 | 上院一零零 |
| 习近平新时代…概论（18 字） | 整段播（最长匹配支持 40 字） |

`tts.py` 按「最长匹配」取用：有整段就用整段，没有就退回逐字拼。
作业和日程的词汇是封闭的（一学期就那些课、那些教室），所以生成一遍就基本全覆盖。

**漏字会自愈**：播放时缺哪个字，会记进 `resources/voice/_missing.txt`，
下次跑 `gen_voice.py` 自动把缺的字补上——不用自己去找少了什么。

## 配置（都有默认值）

| 变量 | 默认 | 说明 |
|---|---|---|
| LLM_API_KEY | local_secrets.py | 必填 |
| LLM_BASE_URL | models.sjtu.edu.cn/api/v1 | OpenAI 兼容地址；不在校园网就换成自己的 |
| LLM_MODEL | deepseek-chat | 别用 reasoner，语音场景要的是快 |

| BACKEND_TOKEN | 空 | 电脑端 `NAIWOZHU_ACCESS_KEY` 的值，走局域网时两边填一样 |
| STALE_HOURS | 24 | 交我办快照超过这么多小时没更新，播报日程时补一句"可能不是最新的" |
| WAKE_WORD | 奶龙你好,哪种你好,… | 唤醒词，逗号分隔可以写多个，命中任意一个都算 |
| WAKE_REGEX | `[奶哪那乃奈][龙笼隆荣农牛]` | 同音字族正则，见下；设 `0` 关掉 |
| WAKE_GRAMMAR | 空 | 填 `"你好 小助手"` 可限定词表降 CPU（只能用模型词表里已有的词） |
| DENOISE | 0 | 降噪开关 |
| STT_ECHO | 1 | 1=实时打印识别到的文字（排查语音时最有用），0=静默 |
| ACK | 1 | 1=唤醒后应一声"我在"；想一口气说完就设 0 |
| SYSTEM_TTS | 0 | 1=用系统语音念（临时，没有奶龙素材时用） |

| WHISPER_SIZE | base | `base` 是甜点；要更准改 `small`（慢 3 倍） |
| CLOUD_ASR_PROVIDER | baidu | `baidu` / `openai` |

| CLOUD_ASR_BASE / MODEL | SiliconFlow | `openai` 兼容的地址和模型名 |

## 调不准的时候

**说了唤醒词没反应**：`[stt] 听到:` 会实时打印它听成了什么（默认就开，见 `STT_ECHO`），
照着改 `WAKE_WORD` 即可；觉得太吵就 `STT_ECHO=0`。
识别得不对就把它加到 `WAKE_WORD` 里（逗号分隔，可以写多个）。

### 关于"奶龙"这两个字

`奶龙` 不在 Vosk 中文小模型的词表里，所以它**永远拼不出这两个字**，只会输出同音词。
实测（合成音频喂进去看模型吐什么）：

| 你想说的 | 模型听成 |
|---|---|
| 奶龙你好 | **哪种你好** |
| 那楼你好 | 那楼你好 |
| 奶农你好 | 奶农你好 |
| 奶牛你好 | 奶牛你好 |
| 奈龙你好 | 内容你好 |
| 奶龙 | 哪荣 |

所以默认的 `WAKE_WORD` 把这几个同音说法都列上了，你随便说哪个都能唤醒。
如果实际用起来又冒出新的听法，把它追加进这一行就行，不用改代码。

### 为什么还要一条正则

同一个唤醒词，**每次识别出来的字都不一样**（实测同一段音频："那句你好" / "奶农您好" /
"哪笼鸟" / "哪种你好"）。靠穷举别名永远追不上，所以还有一条同音字族正则：

```python
WAKE_REGEX = "[奶哪那乃奈][龙笼隆荣农牛]"     # 两个同音字就算唤醒
```

只放了两组字：第一组是 n-声母、ai/e 韵母，第二组是 l/r-声母、ong/ou 韵母。
**故意不含"内/容"**，因为"内容"是常用词，放进去会天天误唤醒。

另外匹配前会把"您"当作"你"——踩过一次：模型把"奶农你好"听成"奶农您**好**"，
就差这一个字，唤醒一次都没触发。

真被误唤醒了，就 `WAKE_REGEX=0` 关掉它，只走精确别名。

**听不清 / 老被打断**：`VAD_THRESHOLD` 调大更不容易被噪声打断，调小更不容易"没听见你说话"。
降噪对空调风扇有用，对旁边人说话这种忽大忽小的噪声帮助有限——把麦克风挪近最有效。

**说出的话缺字**：终端会提示 `[tts] 缺素材 N 处`，缺的字重跑一次 `gen_voice.py` 补上。
