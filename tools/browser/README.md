# 奶我助 · 浏览器端

这里的三个文件是**同一件事的三种装法**，装哪个都行。

```
naiwozhu.user.js   同一份脚本：扩展 / Tampermonkey / 控制台 都用它
manifest.json      Chrome 扩展清单（MV3）
background.js      扩展的后台，负责跨域那一跳
```

## 三种装法

### ① 装成「奶我助」自带的扩展

不需要管理器，不需要访问任何扩展商店，也不需要联网装东西。

1. 浏览器地址栏输入 `chrome://extensions`
2. 打开右上角的**开发者模式**
3. 点「**加载已解压的扩展程序**」，选中 `tools/browser` 这个目录
4. 打开 `calendar.sjtu.edu.cn/ui/calendar`，右下角会出现「奶我助」面板

「奶我助」的配置页上直接显示这个目录的绝对路径，还有一个「复制路径」按钮，
不用自己去找。

### ② 装进 Tampermonkey / Violentmonkey

把 `naiwozhu.user.js` 装进管理器。配置页上有 Edge 商店的安装链接
（国内一般能直连），也有官网链接给其他浏览器。

### ③ 什么都不装

在日历页上按 F12 → Console，把 `naiwozhu.user.js` 全部内容粘进去回车。
会下载一个 JSON 文件，拖进「奶我助」网页。

## 为什么跨域那一跳要单独放一个后台文件

浏览器不允许**网页**随手往 `http://127.0.0.1` 写数据——那正是跨域规则在管的事。
要放行，本地服务就得加 CORS 头；而只要加了，**你浏览器里访问的任何一个网页**
都能往你的本地服务 POST，伪造日程或者把你的课表读走。

扩展的后台（service worker）不受网页那套规则约束：`manifest.json` 里声明了
`host_permissions`，它就能直接请求 `127.0.0.1`。所以：

| 装法 | 跨域那一跳谁发 | 本地服务要加 CORS 吗 |
|---|---|---|
| 扩展 | 后台 service worker | **不用** |
| Tampermonkey | `GM_xmlhttpRequest` | **不用** |
| 控制台 | 不推，落成文件 | 不用 |

分工是刻意的：内容脚本只干"在日历页上取数"一件事，把"碰网络"集中在后台。

## 它不是后台任务

浏览器关着就不会同步。三种装法都依赖你打开交我办日历页
（只有扩展和 Tampermonkey 这两种是打开就自动跑，不用你点）。

## 权限说明

- `content_scripts.matches` 只有 `https://calendar.sjtu.edu.cn/*` —— 别的网站它不进
- `host_permissions` 只有 `http://127.0.0.1/*` 和 `http://localhost/*` —— 只发给本机
- `storage` —— 只用来记"上次同步是什么时候"，好做最小间隔

脚本不登录、不读也不导出 cookie、不碰密码。它是在**你已经登录的那个页面自己的源里**
发请求，浏览器自动带上会话。数据只送到 `127.0.0.1`，不经过任何第三方。
