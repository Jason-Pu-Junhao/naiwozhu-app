### 1.2 四个新接口（终端只用这几个）

| 方法 | 路径 | 用途 | 谁能用 |
|---|---|---|---|
| `GET` | `/api/items` | 条目列表（已合并隐藏）；`?kind=日程` 过滤；`?hidden=1` 只给被隐藏的 | 全部 |
| `PATCH` | `/api/item/<id>` | 改一条 | 只有 `manual-*` |
| `DELETE` | `/api/item/<id>` | 删一条 | `manual-*` 删除；`cal-*` 隐藏 |
| `POST` | `/api/item/<id>/restore` | 撤销删除 / 撤销隐藏 | 全部 |

`PATCH` 入参用短名，服务端落库时换成存储名：

| 请求里写 | 落库字段 | 适用 |
|---|---|---|
| `title` | `title` | 两者 |
| `start` / `end` | `start_at` / `end_at` | 日程 |
| `due` | `due_at` | 截止 |
| `location` / `course` / `note` | `location` / `course` / `description` | 按类型 |
| `all_day` | `all_day` | 日程 |

**错误码**（终端要按码给不同话术）：

| 码 | 含义 | 终端该怎么说 |
|---|---|---|
| `400` | 字段不认识、`kind` 被改、时间解析不出来、标题为空 | 「这条我改不了，换个说法」 |
| `404` | 条目不存在，或已经被删掉 | 「没找到这条，可能已经删了」 |
| `409` | 只读来源：Canvas 截止，或 `cal-*` 想改时间 | 「交我办里的课表改不了。要不要把它隐藏、再加一条下午的？」 |
| `422` | 结束时间早于开始时间 | 「结束比开始早了，再说一次时间」 |
| `401` / `403` | 口令问题（原来就有） | 「这台机器还没配好口令」 |

### 1.3 语义边界（必须照做）

1. **交我办的课表不能改时间。** `PATCH /api/item/cal-*` 一律 409。
   用户说「把明天第一节改到下午」时，正确流程是两步：
   ① `POST /api/manual` 新增一条下午的日程（`note` 里写 `改期自 cal-xxxx`）；
   ② `DELETE /api/item/cal-xxxx` 隐藏原来那条。
   **顺序固定：先加后隐**，新增失败就别隐藏，免得两条都没了。
2. **所有写操作都只在本机生效。** 接口返回里带 `effective.local_only = true` 与 `tip`；
   播报时把这句带上（「只在本机生效，交我办里还是上午八点」），不要写死在话术里。
3. **删 / 隐藏都要确认。** 单轮改多轮：先复述「是这一条吗」，收到「对」再写。
   撤销走 `restore`，口误改错要有退路。

## 二、给终端同学的 prompt（可整段复制）

下面这段是写给人/给 agent 的，可以直接粘到 `naiwozhu-terminal` 那个会话里：

> 电脑端的条目接口已经上线（仓库 `Jason-Pu-Junhao/naiwozhu-app`，接口见 `API.md` §1.7–1.9、§2.5），
> 现在要把终端从「只查询」接到「能删、能恢复、能改手动条目、能隐藏交我办条目」。请按下面做：
>
> **1）`backend.py`** 新增三个方法，风格照现有的 `manual_delete()`：
> - `item_update(item_id, fields)` → `PATCH /api/item/<id>`
> - `item_delete(item_id)` → `DELETE /api/item/<id>`（`manual-*` 是删除，`cal-*` 是隐藏，同一个调用）
> - `item_restore(item_id)` → `POST /api/item/<id>/restore`
>
> 三个方法都要把 400 / 404 / 409 / 422 区分出来，抛出的异常里带上 `status` 和服务端的 `error` 文本，
> 不要把所有失败都变成一句「操作失败」。409 要看 `code == "readonly_source"`。
>
> **2）`llm.py`** 扩输出 schema：现在只有 `{intent, kind, range, start_date, end_date, course}`。
> 新增 `action`（`delete` / `restore` / `reschedule`）、`target`（哪一条：日期 + 第几节 + 课程名）、
> `change`（改成什么：`{"start": "14:00"}`）。
> 每个新字段都要有白名单与降级（模型乱填时当没抽到，回到「再问一句」）。
> 「改时间」类请求**不要**产生 `action: "update"`，统一映射成 `reschedule`。
>
> **3）`assistant.py`** 把 `handle()` 从单轮改成带 `pending` 的多轮：
> - 候选 0 条 → 「没找到符合条件的条目」；
> - 1 条 → 复述确认；
> - 多条 → 逐条念序号让用户选；
> - 收到「对 / 确认」才写；「不对 / 取消」或 15 秒没说话就清掉 `pending`。
>
> `intent == "adjust"` 现在直接回 `write.wip`，这一支要拆开：
> - `action == "delete"` → `backend.item_delete()`
> - `action == "restore"` → `backend.item_restore()`
> - `action == "reschedule"` → **两步**：先 `backend.manual_add()` 加一条（`note` 写 `改期自 <原 id>`），
>   成功后再 `backend.item_delete(<原 id>)` 隐藏原条目；播报带「只在本机生效」。
>   如果用户说的是 `manual-*` 的条目，才可以直接 `item_update()` 改时间。
>
> **4）`tts.py` + 素材**：新增模板 `confirm.delete` / `confirm.reschedule` / `ok.delete` /
> `ok.hide` / `ok.restore` / `ambiguous` / `readonly` / `cancelled` / `fail`；
> 重跑一次 `gen_voice.py`（规则是「文件名 = 念的文字」）。
>
> **5）验收**（先用 `--say` 走文字链路，再上语音）：
> - 「删掉明天的高数」→ 复述确认 → 删掉后紧接着问「明天有什么」→ 高数不出现；
> - 「撤销」→ 高数回来；
> - 「把明天第一节改到下午两点」→ 确认 → 播报含「只在本机生效」；
>   问「明天有什么」→ 上午那条不在、下午那条在，来源写着「手动录入」；
> - 对一条 **Canvas 截止**说「删掉」→ 明确回绝，不是静默失败；
> - 全程 `python assistant.py --check` 与现有测试仍然通过。
>
> 接口细节、返回体、错误码见 `API.md` §1.7–1.9；产品语义（为什么交我办只能隐藏）
> 见电脑端仓库的 `docs/DESIGN_日程修改删除.md`。

## 三、接手前要知道的坑

| 坑 | 说明 |
|---|---|
| **不要升同步版本号** | `SCHEMA` 必须还是 1。升到 2 之后，没升级的那台会在 `validate()` 里直接拒收整包（测试里有一条用例专门守这个） |
| **恢复不是物理删** | 恢复写 `deleted: false`、`rev+1` 的记录。物理删掉的话对端还留着那条墓碑，下一次同步会把它复活 |
| **合并要在过滤之前** | 隐藏的剔除必须发生在 `in_window()` 之前，否则数量与「这一窗有没有内容」都会错 |
| **两层字段名** | API 收 `start` / `end` / `due` / `note`，落库是 `start_at` / `end_at` / `due_at` / `description`；写错名字等于没改 |
| **`cal-*` 的 id 会漂移** | 交我办事件缺 `eventId` 时 id 由 `标题|开始|结束` 拼成，上游改时间 id 就变，隐藏失效。`/api/status` 的 `orphan_hides` 能看到这种情况 |
| **孤儿清理** | 导入 / 同步收包后会自动清「对应条目已经不存在」且放了 30 天以上的隐藏记录；别在别处提前清 |
